## 一句话

Agent 会话在 GPU 推理和 CPU 工具调用之间来回切换，现有调度器挑会话时既不知道工具什么时候返回，又是一个一个贪心地放。TAO 把"缓存信用、工具是否就绪、上下文长度"按固定优先级排成三元组，再在节点容量约束下对整个等待池做一次动态规划。在论文报告的 12 组设置里，相对每项指标上最好的基线，端到端延迟最多降 26.8%，平均 TTFT 最多降 36.3%，解码吞吐最多升 29.5%。

"最多"两个字要留意：同一组表格里也有 TAO 落后的格子，第 6 节会列出来。

## 1. 问题：工具调用把推理切成了碎片

SWE-agent、Claude Code 这类 Agent 的一个任务由多轮组成：模型生成工具调用，交给外部 CPU 环境执行（跑测试、编译、检索），拿到结果拼回上下文，再请求下一轮推理。论文把这种部署叫 **CGDC**（Clustered GPUs with Distributed CPUs）：GPU 节点集中提供推理，工具在独立的 CPU/内存预算上运行。

论文图 1 左下角的条形图给了一个数：在他们的负载里，工具调用占了端到端时间的 93.1%，推理只占 6.9%。既然大部分时间 GPU 用不上，调度器就可以在工具边界做**会话中断**，释放该会话的准入额度，把它放进等待池；工具返回后再做**会话重启**，挑一个节点重新准入。这套生命周期沿用自 ThunderAgent（Kang et al., 2026），TAO 关注的是"从等待池里挑谁、放哪"。

![论文图 1。左：CGDC 场景，外部工具调用在两次 LLM 请求之间留下空档，工具时延占 93.1%。右：现有 evaluate-then-decide 调度器的两个问题，一是评估时忽略工具返回就绪度、用启发式规则合并特征，二是逐个会话做短视的准入和放置决策。](../../assets/papers/tao/figure-1-cgdc.png '图 1（原图）：CGDC 场景与现有调度器的两个缺陷。来源：Li et al., 2026，CC BY 4.0。')

现有系统（llm-d、SGLang、Dynamo、ThunderAgent 等）大体是"先评估、后决策"，论文认为两步各有一个缺口：

- **评估**：看 KV Cache 亲和性、Token 数、SLO，但不看工具什么时候返回；多个特征靠手调的加权或阈值合成一个分数。
- **决策**：每个会话单独打分、单独路由。几个"短但缓存命中低"的会话可能先占掉容量，把"工具已返回、缓存命中高"的会话挡在外面。

## 2. 方法总览：用三元组代替加权和

![论文图 2。TAO 的 evaluate-then-decide 框架：分布式 CPU 侧提供工具调用的历史耗时，GPU 侧引擎提供缓存观测；会话评估模块为每个会话-节点对构造三元组（衰减后的 KV 缓存信用、二元就绪度、Token 数）；决策模块用异步动态规划联合选择并放置等待中的会话，执行前按实时状态重新校验。](../../assets/papers/tao/figure-2-pipeline.png '图 2（原图）：TAO 的两阶段流水线。来源：Li et al., 2026，CC BY 4.0。')

设等待池为 $P$（被中断的会话加新到达的会话），快照里的 GPU 节点集合为 $B$。会话 $i$ 的准入成本是 $w_i$，节点 $b$ 的剩余容量是 $C_b$，$E$ 是允许的会话-节点对。可行域是：

$$
\mathcal{X}=\left\{x:\ \sum_{b\in B}x_{i,b}\le 1,\quad \sum_{i\in P}w_i x_{i,b}\le C_b,\quad x_{i,b}=0 \text{ if } (i,b)\notin E\right\} \qquad (1)
$$

每个可行的会话-节点对得到一个三元组，目标是按字典序最大化选中三元组之和：

$$
v_{i,b}=\left(k_{i,b},\ r_i,\ t_i\right),\qquad x^\star\in\operatorname*{arg\,lexmax}_{x\in\mathcal{X}}\ \sum_{i\in P}\sum_{b\in B}x_{i,b}\,v_{i,b} \qquad (2),(3)
$$

三个分量的优先级是固定的：

1. $k_{i,b}$，**衰减后的缓存信用**。命中前缀直接省掉 Prefill，所以排第一；但它随暂停时间快速衰减。
2. $r_i\in\lbrace 0,1\rbrace$，**工具返回就绪度**。第一项衰减到打平之后，由它区分"马上要回来"和"还早"的会话。
3. $t_i$，**累积 Token 数**。前两项都打平时偏向上下文更长的会话；它占的容量更大，这笔账由后面的 DP 去算。

用字典序而不用加权和，好处是不用调权重：不同量纲的特征不会互相抵消。代价是表达力变窄，第一项只要差一点点，后两项就完全不起作用。TAO 靠下一节的衰减和取整来缓解这一点。

## 3. 两个信号：缓存信用怎么衰减，工具什么时候回来

### 3.1 缓存信用的时间衰减

会话因工具调用暂停时，它在节点 $b$ 上留下的前缀不会一直在：其他请求在跑，引擎会按自己的策略驱逐 KV 块。论文在 DeepSeek-V4 Flash（2 节点 × 4 H100）的轨迹上统计了"暂停多久之后，下一次请求还能命中多少缓存"，也就是图 3。

<CacheRetention />

TAO 对观测到的缓存信用 $k^{0}_{i,b}$ 按暂停时长打折，并对结果取整：

$$
k_{i,b}(t)=k^{0}_{i,b}\,2^{-\tau_{i,b}/h},\qquad \tau_{i,b}=\max\left(0,\ t-t^{\mathrm{obs}}_{i,b}\right) \qquad (4)
$$

论文取 $h=10$ 秒。这里有一个容易读错的地方：**$h$ 不是对缓存保留率的拟合**。论文明确说半衰期是调度参数，和轨迹拟合出的时间常数是两回事。对比一下就清楚了：暂停 44 秒时实测中位数还有 91.4%，而 $h=10$ 的信用只剩 $2^{-4.4}\approx 4.7\%$。

我的理解是，衰减在这里的作用主要是**让出优先级**：信用很快被压低、取整后打平，第二项 $r_i$ 才有机会起作用。滑块拉到 60 秒能看到，衰减变慢后，第一项会在更长时间里独占排序。论文没有报告 $h$ 的敏感性实验，取 10 秒是怎么定的，正文没有交代。

另外，图 3 的中位数不是平滑下降的：44 秒以内都在 90% 以上，87 秒之后直接归零，中间那两个分箱的 95% 区间覆盖了 0 到 96%。"指数衰减"是描述性拟合，真实形状更像一个阈值。

### 3.2 工具返回就绪度

TAO 要回答"这个会话的工具会不会在接下来 $H$ 秒内返回"。论文取 $H=1$ 秒，和调度周期一致。信号按可信度依次取：

1. 工具接口直接暴露的进度或截止时间，例如 Claude Code 的 Monitor 事件、OpenCode 的 Bash 超时信息；
2. 从命令里解析出的 `sleep N`；
3. 按结构化工具名统计的历史耗时；没有该工具的历史就用全局历史，再没有就用 5 秒默认值。

历史估计用了一个经验 Bernstein 形式的保守上界（附录 A，Maurer & Pontil 2009），$\delta=0.2$：

$$
\widehat{D}_f=\bar{d}_f+\sqrt{\frac{2s_f^2\log(3/\delta)}{n_f}}+\frac{3R_f\log(3/\delta)}{n_f}\qquad (n_f\ge 2) \qquad (8)
$$

减去已执行时间 $e_i(t)$ 得到剩余时间 $\hat d_i(t)=\max\lbrace 0,\ \widehat D_f-e_i(t)\rbrace$。二元信号 $r_i(t)$ 的规则是：

- 工具已经完成，直接置 1，优先于任何预测；
- 预测完成时间落在 $t+H$ 以内，且预测时间戳在 30 秒内刷新过，置 1；
- 预测时间已过但工具还没回来，只给一个临时的探针机会，不会一直占着"就绪"。

论文自己也说，这个上界是调度启发式，不保证单次调用的覆盖率。实际效果看附录数据：在 10,967 次完成的工具调用上，最终预测的平均绝对误差是 0.410 秒，82.9% 的误差在 0.5 秒以内，也就是半个调度周期。

## 4. 决策：多背包动态规划，加一层异步

### 4.1 为什么贪心不够

拿到每个会话-节点对的三元组后，最直接的做法是按分数从高到低往节点里塞。问题在于各会话的 $w_i$ 差别很大，缓存命中又强烈依赖节点。局部看合理的一步，可能把一个节点的剩余空间切碎，或者占掉某个只在特定节点上有大量缓存的会话的位置。附录 H 给了两个重建的真实快照，下面按原图坐标重画。

图 10 里，贪心先把较短的 P89、P123 放进 Node 1，于是 P109（在 Node 1 上有 8.8k 命中）和 P111（6.6k 命中）只能去没有缓存的 Node 2。DP 反过来安排，两边总的剩余安全空间相同，缓存信用从 13,624 增加到 16,791，多 23.2%。

<Placement figure="fig11" />

图 11 是准入数量的例子。贪心先把四个短会话塞进 Node 1，两个节点各剩约 14k 和 15k，都放不下约 21k 的会话 177，只准入 6 个；DP 把 195、193 挪到 Node 2，在 Node 1 腾出整块空间，准入 7 个。

这两张图是精选的例子。论文第 4.3 节给了更全面的统计：在 23 个有多个候选会话的快照里，DP 在 6 个（26.1%）上改进了字典序目标，其余 17 个和贪心结果相同；算上单候选的情况，35 个快照里改进了 6 个（17.1%）。**多数时候 DP 和贪心给出同一个答案**，差距来自少数快照。

### 4.2 动态规划

令 $\Delta$ 为容量量子，离散化后会话成本 $\bar w_i=\lceil w_i/\Delta\rceil$，节点容量 $\bar C_b=\lfloor C_b/\Delta\rfloor$。$D_j(s)$ 表示只考虑前 $j$ 个会话、各节点已用容量为向量 $s$ 时能达到的最大字典序价值：

$$
D_j(s)=\operatorname*{lexmax}\left\lbrace D_{j-1}(s),\ \operatorname*{lexmax}_{b\ \text{eligible}}\left[D_{j-1}(s-\bar w_j e_b)+u_{j,b}\right]\right\rbrace \qquad (7)
$$

状态是多维的，节点一多就会爆。论文的两个工程处理：缓存等价的节点合并成 $g\le m$ 个容量维度；设状态预算，超了就退回 BFD（best-fit-decreasing）。

### 4.3 异步求解与重验证

为了不阻塞调度主循环，DP 在独立的异步 worker 里对时刻 $s$ 的冻结快照求解，得到计划 $x_s$。在时刻 $t$ 应用前做重验证：被选中会话的状态签名变了就丢弃整个计划；否则只应用当前实时容量允许的最长可行前缀 $y_t$。

论文给了相对于"在 $t$ 时刻重新求最优"的损失上界：

$$
\max_{x\in\mathcal{X}_t^\Delta}U_t(x)-U_t(y_t)\ \le\ A_{s,t}+2\epsilon_{s,t}+T_{s,t} \qquad (10)
$$

$A_{s,t}$ 是可行域变化带来的新机会，$\epsilon_{s,t}$ 是规划期间的价值漂移，$T_{s,t}$ 是重验证截断造成的损失。这个界是**有条件的**：若每个计划最多 $K$ 个分配、单个分配的价值漂移有界，并进一步假设漂移随时间线性增长 $\eta_{s,t}\le L(t-s)$，漂移项才变成 $2KL(t-s)$。论文特别指出，二元就绪度的跳变不满足这个假设，需要单独留余量。所以它更适合理解为"规划越新鲜，损失越小"的定性保证，而不是可以直接代入的数。

## 5. 实验设置

- **模型与硬件**：DeepSeek-V4 Flash（2 节点 × 4 H100），Qwen3-32B（4 节点 × 2 H100，4 副本），GLM-4.7（单节点 8 × H100，TP8）。
- **负载**：SWE-bench Lite（SWE-Lite，用 mini-SWE-agent 驱动）；DeepSeek 另跑 Terminal-Bench 2.0（用 Claude Code 驱动）；Qwen 与 GLM 另跑 SWE-verified。GLM 每次运行 300 个任务。
- **基线**：Dynamo（KV 感知调度）、vLLM 调度器配 Round-Robin（RR）或 Cache-Aware（CA）路由、ThunderAgent（按 Token 数排序 + BFD 放置）。
- **指标**：任务端到端平均延迟、平均 TTFT、解码吞吐。

## 8. 我的看法

**值得借鉴的地方**

- **字典序加衰减，用来代替手调权重**。很多网关路由写成 `score = w1 * cache + w2 * load + w3 * wait`，换个负载权重就得重调。TAO 用固定优先级，让第一项随时间衰减、取整后打平，把排序权自然交给第二项。思路简单，可以直接搬到别的多信号调度里。
- **"异步求解快照 + 应用前校验 + 截取可行前缀 + 超时回退"这套组合**，是把精确组合优化放进在线调度的一个稳妥做法。表里能看到它的代价：并发上去后回退率到了 9%，但不会卡住主循环。
- **和 Agentic RL 的 rollout 很像**。多轮 Agent RL 的 rollout 阶段本身就是 CGDC：大量轨迹卡在容器编译和单测上。把就绪度和联合准入放进 RL 框架的 rollout 调度器，可能缓解长尾轨迹拖慢整个 step 的问题。这是我的推测，论文没有做 RL 场景的实验。

**需要留意的地方**

- 收益集中在高并发、容量紧张的设置；低并发时和最强基线只差几个百分点，个别格子还落后。
- 消融显示主要收益来自 DP 放置，而第 4.3 节统计 DP 只在约四分之一的多候选快照里改变了结果。两者合起来看，收益来自少数关键决策，这也解释了为什么低并发时差距很小。
- $h=10$ 秒、$H=1$ 秒、$\delta=0.2$ 这些参数都是给定值，没有敏感性分析；主表也没有方差。
